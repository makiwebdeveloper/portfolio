## Ветки

- `main`: единственная ветка, стиль «Скетчбук». Сайт выглядит как лист тетради, нарисованный маркером и собранный из бумаги: дрожащие линии, бумажное зерно, вырезанные карточки на скотче, рукописные заголовки. Стикмен по-мультяшному прыгает между секциями, курсор сделан карандашом. Интерфейс аккуратный, без визуального шума. Первая версия (WebGL-орбы, Tonami Komuro) осталась только в истории коммитов (`ca6e0fc`).

## Команды

```bash

npm run build      # astro check (типы) + сборка; должна проходить без ошибок и warnings
```

Порт 4321 может оказаться `npm run preview` (отдаёт `dist/`): тогда правки видны только после `npm run build`.
URL-параметры для проверки: `?no-preloader`, `?theme=day|night`. Тема по умолчанию — день (системная тема не учитывается), ночь только по выбору пользователя.

## Стек

Astro 5 (static, без UI-фреймворка) + TypeScript strict, GSAP 3 + ScrollTrigger, Lenis.
Шрифты self-host через `@fontsource-variable`: **Caveat** (рукописный, для заголовков, подписей и кнопок) и **Nunito** (основной текст). Оба шрифта с кириллицей, потому что есть локаль UK.
Длинные тексты (описания проектов, глав) набираем Nunito, рукописным шрифтом их не пишем: страницу читает рекрутер.
Скрипты пишутся как vanilla `<script>` внутри `.astro`-компонентов. React/Vue не добавлять.

## Стикмен

- Фигура-станция Hero стоит слева от полароида (`.hero__stick-spot` в `.hero__center`): с неё бегун начинает прогулку по Hero. На «синьке» (`.invert`) бегун получает `.is-invert` и рисуется светлым (токены в `tokens.css`). В Work станция в полях отсчитывается от края экрана (секция во всю ширину).
- Бегун (`Stickman.astro`) — **проводник, всегда в кадре**. Живёт на контенте: элементы с `data-perch="<поза>"` — его точки. Они стоят на каждом блоке: фигура Hero, абзац Intro, концы подчёркиваний заголовков (`<Underline perch="…">`), круг года и активная карточка главы в Story, строки проектов, ленты навыков, языки, карточка и кнопки Contact, футер.
  - Атрибуты: `data-perch-edge` (`top` по умолчанию — верхний край; `mid` — середина высоты, для подчёркивания, можно встать за концом линии; `station` — ровно на месте `StickStation`; `path` — у кончика линии `<path>` внутри элемента, прогресс в `data-draw-k`, направление в `data-draw-dir`), `data-perch-at` (0…1), `data-perch-dy`, `data-perch-face`, `data-perch-scale`, `data-perch-span` («0.3 0.72» — по какой части ширины можно бегать), `data-perch-skip` (селектор: точка недоступна, пока элемент ему соответствует). В закреплённой Story карточки глав пропускаются (они прилетают с transform и сменяются): стикмен «рисует» круг-таймер года (`drawAlong`/`penPose` в `Stickman.astro`): стоит снаружи круга прямо, лицом по ходу, толкает огромный карандаш (`pencilProps`), руки держат его через IK (`reachArms`), грифель всегда точно на кончике линии. Скорость кончика задаёт Story, ноги — от неё (быстро — бежит), стоит — дышит. Стирает (`data-draw-dir=erase`) — подскок и переворот карандаша ластиком вниз (`pen.flip`), трёт, летят крошки; на новой главе подпрыгивает к началу круга. Встав к линии, ставит `data-pen="on"`. Когда догоняет на пределе скорости — наклон, чёрточки скорости и капли пота (`hurryFx`, реквизит с `fx: true`).
  - Координаты точек **живые**: пересчитываются на скролле (rAF) и раз в 0.4 с. `perchOf` берёт «итоговое» место блока: вычитает translate, который сейчас анимируется (у самого элемента и у `[data-reveal]`-предка), иначе после посадки его дёргает вслед за блоком. Конец дуги прыжка и путь бега тоже следят за живой точкой; с касания стикмена держит `glue()`. Пока он стоит, `glue()` каждый кадр приклеивает его к своему блоку (sticky-карточки, появление, аккордеон). Во время скролла рендер идёт на 60 fps.
- Выбор точки (`activeIndex`): держится текущего блока, пока тот в полосе 24…90% высоты экрана, иначе прыгает на блок в полосе, ближайший к 62%. Наверху страницы — Hero, в самом низу — футер. Та же высота → **бежит** (поза `run`, фаза шага от пройденного пути), иначе **прыгает** (замах → дуга, дальние с сальто → приземление с пылью → поза точки).
- **Свободная жизнь только в Hero** (`roam`, см. ниже). В остальных секциях он идёт по сценарию: прыгает/бежит на точку и стоит в её позе, ничего не делает сам (`scheduleIdle` срабатывает только при `target === 0`; пробежки, подскоки, помахать и оглянуться вне Hero убраны по просьбе).
- Без JS и при reduced motion видны статичные `<StickStation class="lane-station">` в полях (иллюстрации). При `.has-runner` они `display: none`. Фигура Hero остаётся в потоке (по ней меряется точка).
- Новая поза: имя в `POSES`, `case` в `pose()` и при необходимости реквизит в `propsFor()`. Позы движения (`crouch`, `jump`, `run`, `walk`, `fall`, `skid`, `surf`, `sit`) лежат в `MotionPose`. У `run`/`walk` вместо времени фаза от пройденного пути (`st.phase`).
- Самолётик из позы `plane` летит в `[data-plane-target]`, цель получает класс `.is-hit`.
- **Прогулка по Hero** (`roam` в `Stickman.astro`, режим `mode = 'roam'`, пока бегун на станции Hero). Поверхности — элементы с `data-roam`: `text` (верх строки по `Range`), `box` (верхний край блока с учётом наклона `rotate` у него и предков), `mid` (середина высоты, подчёркивание); `data-roam-dy` — сдвиг вниз в долях высоты, `data-roam-span="0.4 0.6"` — где по ширине можно стоять. Берутся только поверхности в кадре. Он **фон, а не главный герой**: двигается неторопливо, как в мультике (пользователь просил не «СДВГ»). Между действиями (`flow`) обычно стоит 1–3.5 с, сразу продолжает только в 30% случаев. Переходы: та же высота рядом — чаще идёт шагом (`runTo` с `gait`/`speed`/`ease`, длина шага `stride` соответствует позе, чтобы ноги не мельтешили); ниже и в стороне — подходит к краю и срывается (`leap` с `air: 'fall'`); иначе прыгает с замахом или с короткого разбега (`takeoff: 'run'`), сальто редко (`flip`), весь прыжок замедлен (`slow: 0.75`), приземление `quick`, потом пара шагов по инерции, редко кувырок (`roll`). Чаще возится на своём блоке (70%), чем перебирается; когда перебирается, выбирает средне-дальние блоки (колокол вокруг 60% от самого дальнего, ближе 140px почти никогда), чтобы не топтаться в одном месте. На блоке: больше половины действий — прогулка шагом (чаще в дальний конец), сидит на краю (3–5.5 с), оглядывается, машет; реже пробежка с торможением (`skid`), вприпрыжку (`skipHops`), сальто на месте (`flipHere`). Быстрее не делать. Лазанья по бокам нет (убрано по просьбе). Ждёт `.is-drawn` у Hero, стоит при `.is-still`. На ресайзе возвращается на станцию. Схватить/бросить больше нельзя.

## Правила, которые нельзя нарушать

### Цвета

- Цвет задаётся **только** в `tokens.css`. В компонентах используем семантические токены: `--color-bg`, `--color-text`, `--color-muted`, `--color-line`, `--color-accent`, `--color-surface`, `--color-highlight`, `--color-tape`, `--color-margin`, `--color-shadow`, `--color-particle`. Сырые `--p-*` берём только там, где нужен «чистый» цвет (жёлтый стикер). Карандаш курсора — `--pencil-*`.
- Никаких hex/rgb в компонентах. Исключение: обложки проектов в `ProjectVisual.astro`, они строятся из `oklch(... var(--h))`, то есть от hue проекта.
- Canvas-слои (след карандаша) перечитывают цвета по событию `colorschange`.

### SSR и модули

- `src/lib/theme.ts` и `src/lib/motion.ts` при импорте обращаются к `document`/`window`. **Импортировать их можно только в `<script>`**, во frontmatter нельзя. `stickman.ts` SSR-безопасен.
- `motion.ts` работает как синглтон. Lenis и `gsap.registerPlugin` не создавать повторно в компонентах.
- Модульные скрипты Astro выполняются в произвольном порядке. Если нужна синхронизация, используем промисы или события (`introDone`, `colorschange`), а не порядок подключения.

### Прогрессивное улучшение и доступность

- Без JS страница должна быть полной и читаемой: станции видны как иллюстрации, рамки и бумага сделаны на чистом CSS и SVG. Скрывающие стили пишем только под `.js`.
- `prefers-reduced-motion` отключает Lenis, курсор, scrub-анимации, pinned-Story, boil и прыгуна (станции стоят на месте). Каждую новую анимацию проверяй в этом режиме.
- Кнопка паузы в шапке ставит `html.is-still`: останавливает boil, бегущие строки и живые позы. Новые бесконечные анимации тоже должны слушаться `.is-still`.
- Кастомный курсор только при `(hover:hover) and (pointer:fine)`. `data-cursor="Text"` даёт записку с подписью, `data-magnetic="0.25"` даёт магнитный эффект.
- Секции-цели якорей имеют `id` + `tabindex="-1"`. Аккордеоны строятся на `button[aria-expanded]` + `region`, у закрытой панели стоит `inert`.
- Декоративное (станции, прыгун, вторая лента marquee) помечается `aria-hidden="true"`.

### Производительность

- Анимируем только `transform`/`opacity`/`stroke-dashoffset` (и CSS-переменные). Появление делаем через `initReveals`. ScrollTrigger используем, только когда нужен scrub или pin.
- Бюджет JS: **≤ 80 КБ gzip** на главную (сейчас ~61 КБ).
- **Никаких огромных SVG/слоёв, которые меняются на каждом кадре скролла** (именно так тормозила первая версия стикмена с линией во всю страницу). Никакого `mix-blend-mode` на fixed-слоях поверх страницы (зерно).
- На элементах, которые перерисовываются каждый кадр (стикмен), SVG-фильтры не используем. Проверка:
  `for f in dist/_astro/*.js; do gzip -c $f | wc -c; done | paste -sd+ | bc`
- **Displacement-фильтры (`feDisplacementMap`) только на статичных станциях** (`#rough-stick`). На всём, что перерисовывается (ховеры, аккордеоны, boil, большие площади), они сильно грузят GPU: из-за них тормозила секция проектов. Дешёвые замены: неровный `border-radius` (`--wobble`), boil через смену формы скругления (`@keyframes boil` / `boil-round`), волнистые линии через маску `--wavy-line` (`.rule`).
- Заливки/штриховки при наведении: слой рисуется один раз (`will-change: transform`) и выезжает `transform`-ом. Анимировать `clip-path` по большому `repeating-linear-gradient` нельзя: он перерисовывается каждый кадр.
- Аккордеон проектов анимирует высоту (`grid-template-rows`). Всё, что ниже него (`.project`, `.skills`, `.contact > .container`, `.footer`), лежит в своих слоях (`will-change: transform`), чтобы при сдвиге не перерисовываться. Не ставь `will-change: transform` на элемент с `position: fixed` потомками (тост в Contact).
- Замер: headless + трейс (`page.tracing`) с флагами `--enable-gpu --use-angle=metal`, сумма `GPUTask`/`Paint`/`RasterTask`. Метрика rAF такие лаги не видит.
- Если меняется высота страницы, вызывай `ScrollTrigger.refresh()` после перехода (станции стикмена пересчитаются сами).

### Известные грабли

- У `body` фон **прозрачный**, фон задан на `html`. `main` имеет `z-index: 1`, стикмен (`z-index: 2`) рисуется поверх контента.
- `getPropertyValue('--lane')` возвращает строку `clamp(...)`, а не пиксели. Ширину полей бери из `getComputedStyle(body).paddingLeft`.
- **Не использовать `vector-effect: non-scaling-stroke` вместе с dash-анимацией** (`pathLength="1"` + `preserveAspectRatio="none"`): Chrome рвёт линию. Паттерн для рисуемых линий: `stroke-dasharray: 1 2; stroke-dashoffset: 1.01` → `0` (без точки от round-cap).
- Reset `svg { max-width: 100% }`: SVG внутри обёртки нулевой ширины (карандаш) получает 0. Нужен `max-width: none`.
- Грид-элемент с бесконечной лентой (marquee) растягивает страницу: колонке нужен `minmax(0, 1fr)`.
- У рукописных цифр большие выносные элементы. Высоту ячейки одометра закладываем с запасом (`--cell: 1.3em`).
- Стикмен лежит в координатах страницы, а закреплённые (sticky) блоки едут по странице вместе со скроллом. Всё, что хранится между кадрами рядом со sticky-блоком (прошлое место, скорость, начало прыжка), считай в экранных координатах или смещениями от живой точки, иначе он отстаёт на величину скролла за кадр. По той же причине `render` рисует каждый кадр, когда сменился `scrollY` (Lenis крутит раньше, событие `scroll` приходит позже).
- `localStorage`/`sessionStorage` всегда оборачиваем в `try/catch` (приватный режим).

## Контент и i18n

- Новая строка интерфейса добавляется в `en` в `ui.ts`. Тип `Record<UIKey, string>` заставит добавить её в `sv` и `uk`, иначе билд упадёт.
- Локализованные поля данных имеют тип `Localized` (`{ en, sv, uk }`), читаются через `pick(value, lang)`.
- Сайт показывает работу, а не биографию. Локация (Стокгольм) только в Hero: координаты лесенкой и посадочный талон. Story один раз упоминает переезд в Швецию. В остальных местах город и статус «живу в…» не повторять: такие детали обсуждаются на собеседовании, и при переезде или новой работе их не придётся менять по всему сайту.
- Story: учёба и работа по годам (`timeline.ts`: `place`, `role`, `period`, `title`, `text`), заголовок «From `hello world` to production»: фраза в обратных кавычках становится одним словом-плашкой кода (`.kw--code`).
- Только факты из резюме (`public/Illia-Makovetskyi-Resume.pdf`, он же скачивается с сайта). Ничего не выдумывать. Если данных нет, спроси пользователя или оставь `TODO`.
- Всю графику (стикмен, карандаш, каракули) рисуем сами кодом, чужие ассеты не берём.

## Как проверять изменения

1. `npm run build`: 0 ошибок, 0 warnings.
2. Визуально: Chrome-расширение (claude-in-chrome) на `npm run dev`. Если оно недоступно, подойдёт headless Chrome с `puppeteer-core` (`executablePath: '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'`). Скрипты для скриншотов кладём в scratchpad, не в проект. Проверь, на каком порту поднялся dev (4321 может быть занят другим сервером).
3. Проверяй обе темы, ширину 390px и 1440px, `?no-preloader`, reduced motion, отсутствие горизонтального скролла и ошибок в консоли.
4. Коммиты делаем только по просьбе пользователя.
